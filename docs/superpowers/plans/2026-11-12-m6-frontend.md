# M6 Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small React SPA with three areas (documents, ask with a streaming verified answer, history). It runs under `docker compose up` next to the API, and CI builds and tests it.

**Architecture:** The app is React + TypeScript + Vite in `frontend/`. It has no router and no state library: `App` switches between two tabs with `useState`, and each page keeps its own state. All HTTP goes through `src/api/` under the path prefix `/api`:
- In development, Vite proxies `/api` to `127.0.0.1:8000`.
- In compose, nginx serves the build and proxies `/api/` to `api:8000`. The browser sees one origin, so the backend needs no CORS.

`POST /ask` is SSE over POST, which `EventSource` cannot do. The app reads it with `fetch` and a small SSE parser instead. Two backend changes come first:
- verification fixes that matter once paragraphs are rendered (fenced code, fullwidth markers);
- `max_attempts` on documents, needed for "retry 2/3".

**Tech Stack:** React 19, TypeScript 5.9, Vite 8 (the template from `create-vite`), Vitest 4 with jsdom and @testing-library/react, nginx (alpine) for the image, npm with a committed `package-lock.json`. Use the versions `npm create vite@latest` and `npm i -D` resolve today, and commit the lockfile.

**Spec:** `docs/superpowers/specs/2026-11-03-fontes-design.md` (sections Frontend, Ask flow, Citations, History, Quality bar)

## Global Constraints

- "The stack is React, TypeScript, and Vite. The owner does not know React, so the frontend must stay simple and conventional, and readable by a backend developer."
- "The frontend is never the focus of the project and should not grow its own complexity: no state-management library unless it is clearly needed." Do not add a router, a markdown renderer, a CSS framework or a data-fetching library either. Use plain CSS in one file.
- Every component is a function component with hooks. API types are written by hand in `src/api/types.ts` and mirror `backend/fontes/api/schemas.py` field for field.
- "CI in GitHub Actions: lint, type check, tests, and a frontend build."
- `docker compose up` brings everything up, the frontend included.
- The UI copy is in English, like the rest of the project.
- Backend rules still hold: `mypy --strict`, ruff, and a test first for every change.
- Commits show only the user's account and carry no AI attribution trailer.

## Review Focus

1. **SSE split at awkward points.** A network read can end mid-event, mid-line, or inside a multi-byte UTF-8 character (Cyrillic answers). Events must arrive whole and the text unbroken. Test: `sse.test.ts`, "events split across reads and inside a UTF-8 character" (Task 3).
2. **`/ask` rejects before streaming.** A blank or too-long question gets a 422 JSON response, not SSE, and the UI must show its `detail`. Test: `AskPage.test.tsx`, "shows the detail of a rejected question" (Task 5).
3. **The stream ends with no verdict and no error.** For example, the api restarts mid-answer. The UI must not stay on "verifying…" for ever; it shows "The connection closed before the answer was verified." Tests: `sse.test.ts` and `AskPage.test.tsx` (Tasks 3 and 5).
4. **Polling the document list.** A document moves queued → processing → ready or failed while the page is open. The list polls while any document is `queued` or `processing` and stops when none is. Delete removes the row at once. Test: `DocumentsPage.test.tsx` (Task 4).
5. **Upload errors.** 413, 415 and 400 must show the API's `detail`, not an nginx HTML page. This needs `client_max_body_size` above the 20 MB limit in nginx, plus a generic message when the body is not JSON. Tests: `client.test.ts` (Task 3); compose is checked in Task 7.

AskPage keeps its view state in one `useState`, typed as a union so impossible combinations cannot exist:

```ts
type View =

  | { kind: "streaming"; question: string; text: string }
  | { kind: "answered"; question: string; verdict: Verdict }
  | { kind: "failed"; question: string; detail: string };
```

`nginx.conf`:
- `location /api/` → `proxy_pass http://api:8000/;`. The trailing slash strips the prefix.
- `proxy_buffering off;` and `proxy_read_timeout 600s;`, so SSE tokens arrive as they are written and a slow first answer (model load) is not cut.
- `client_max_body_size 25m;`, above the 20 MB upload limit, so the api answers 413 with JSON.
- `location /` → `try_files $uri /index.html;`.
