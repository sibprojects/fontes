# M9: Answer-Quality Eval Set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fixed set of questions about the fictional samples, and a command that asks them through a running stack and reports how well Fontes answered.

**Architecture:** `python -m fontes.eval` is a host-side tool in the backend package. It talks to the running API over HTTP, the same path a user takes: `/documents`, `POST /ask` (SSE) and `/questions/{id}`. The cases live in `eval/cases.toml`. Scoring is a set of pure functions: no second model judges the answers. The run prints a Markdown summary and writes a JSON file to `eval/results/`, which is git-ignored.

**Tech Stack:** Python 3.12 stdlib (`tomllib`, `argparse`, `statistics`), httpx (already a dependency), pytest with `httpx.MockTransport`.

**Spec:** `docs/superpowers/specs/2026-11-03-fontes-design.md`. M9 adds no product behaviour; the user asked for "an answer-quality eval set" and opted out of the design questions. The rulings below are mine.

## Rulings (made without the user; listed in the final report)

- **Scoring.** Scoring is deterministic: expected facts are matched as text and language is detected by script. No LLM judge. Results are repeatable and cost nothing, but a correct answer worded differently from the expected text counts as a miss. Alternatives separated by `|` soften this.
- **Path.** The eval runs through the HTTP API of a live stack, not in-process, so it measures what a user gets. One consequence: every eval question is stored in the history.
- **Documents.** It uses only the two samples in `docs/samples/`. It refuses a stack that holds any other document, because foreign documents would change retrieval. It uploads a missing sample. Questions already in the history are allowed.
- **Exit code.** The command exits 0 whenever the run completes, even if cases fail. It is a measurement, not a gate, and it is not added to CI: CI's 0.5B model would only measure that model.
- **Case kinds.** There are two: answerable (names a document and expected facts) and off-topic (expects `not_found`). Questions that sound near a document but are unanswerable are left out, because they cannot be scored without a judge.

## Global Constraints

- **Commits.** Commits carry no AI attribution lines.
- **Backend check.** From `backend/`: `pytest -q -m "integration or not integration"`, `ruff check .`, `ruff format --check .`, `mypy --strict fontes tests alembic`.
- **Dependencies.** No new runtime dependencies.
- **Cases file.** The cases file must not live in `docs/samples/`: the screenshot script uploads every `.md` there.

## Review Focus

1. **Foreign documents.** A stack holding a non-sample document: the command refuses, names each foreign title and asks nothing (Task 3).
2. **Stack not reachable.** The API is down or the URL is wrong: one line naming the URL, exit code 1, no traceback (Task 3).
3. **`error` event.** An `/ask` that ends with an `error` event (model not pulled, timeout): the case is recorded as failed with the detail, and the run goes on (Task 3).
4. **Numbers written with spaces.** "4 800" (also with a no-break or thin space) matches the expected `4800` (Task 2).
5. **A failed sample.** A sample that is in the stack but `failed`: the command refuses and says to delete it and rerun. It does not wait forever (Task 3).

- a question is blank;
- `language` is not in `LANGUAGES`;
- `document` names a file that is not in `samples_dir`;
- an answerable case has an empty `expect`;
- an off-topic case has a non-empty `expect`.

### Task 2: Scoring and the summary

**Files:**
- Create: `backend/fontes/eval/scoring.py`
- Test: `backend/tests/eval/test_scoring.py`

**Interfaces:**
- Consumes: `Case` (Task 1).
- Produces, in `fontes.eval.scoring`:
  - `@dataclass(frozen=True) class Outcome: answer: str; label: str | None; documents: tuple[str, ...]; error: str | None; seconds: float`. `label` is `None` when the stream failed; `documents` holds the titles of the cited sources.
  - `@dataclass(frozen=True) class CaseResult: case: Case; outcome: Outcome; checks: dict[str, bool]`, with a `passed` property that is true when there is no error and every check is true.
  - `detect_language(text: str) -> str`: `"ru"` when Cyrillic letters are the majority of letters, `"zh"` when CJK ideographs are, `"en"` when Latin letters are, else `"unknown"`.
  - `normalize(text: str) -> str`: lower-case it; replace no-break and thin spaces with spaces; remove a space between two digits; collapse runs of whitespace.
  - `score(case: Case, outcome: Outcome) -> CaseResult`.
  - `@dataclass(frozen=True) class Summary: cases: int; passed: int; errors: int; checks: dict[str, tuple[int, int]]; median_seconds: float`. `checks` maps a check name to (passed, applicable).
  - `summarize(results: list[CaseResult]) -> Summary`.
  - `render(summary: Summary, results: list[CaseResult], provider: str | None, model: str | None) -> str`.

The checks for an answerable case:
- `found`: the label is not `not_found`;
- `cited`: `case.document` is in `outcome.documents`;
- `supported`: the label is `supported`;
- `facts`: every `expect` entry has an alternative that is a substring of `normalize(answer)`;
- `language`: `detect_language(answer) == case.language`.

An off-topic case has a single check, `not_found`. When `outcome.error` is set, every check is `False`.

`render` writes a heading naming provider and model (or "unknown"), then a table with one row per check in a fixed order (`found`, `cited`, `supported`, `facts`, `language`, `not_found`) as `passed/applicable`. Then a line with cases passed, errors and the median seconds. Then a list of the failed cases: the id, the failed check names, the error if any, and the first 120 characters of the answer.

### Task 3: The runner and the command

**Files:**
- Create: `backend/fontes/eval/runner.py`, `backend/fontes/eval/__main__.py`
- Modify: `.gitignore` (add `eval/results/`)
- Test: `backend/tests/eval/test_runner.py`

**Interfaces:**
- Consumes: `Case`, `load_cases`, `DEFAULT_*` (Task 1); `Outcome`, `CaseResult`, `score`, `summarize`, `render` (Task 2).
- Produces, in `fontes.eval.runner`:
  - `class StackError(RuntimeError)`: its message is shown to the user as is.
  - `class EvalClient` (async context manager): `EvalClient(base_url: str, *, transport: httpx.AsyncBaseTransport | None = None, ready_timeout: float = 300.0, ask_timeout: float = 600.0, poll_seconds: float = 1.0)`. Methods:
    - `async def prepare(self, samples_dir: Path) -> None`;
    - `async def ask(self, question: str) -> tuple[Outcome, str | None, str | None]`. It returns the outcome plus the provider and model read from `GET /questions/{id}`, or `None, None` when nothing was stored.
  - `async def run(cases: list[Case], client: EvalClient) -> tuple[list[CaseResult], str | None, str | None]`. It asks the cases one at a time, in file order. Provider and model are the first non-null pair seen.
- `__main__`: `main(argv: list[str] | None = None) -> int`.
  - Arguments: `--base-url` (default `http://127.0.0.1:8000`), `--cases`, `--samples`, `--out` (default `REPO_ROOT / "eval" / "results" / f"{UTC %Y%m%d-%H%M%S}.json"`).
  - It prints `render(...)` and writes JSON: `{"provider", "model", "started_at", "base_url", "summary": asdict(summary), "results": [{"id", "passed", "checks", "label", "documents", "error", "seconds", "answer"}]}`.
  - It returns 0 after a completed run. On `StackError`, or an `httpx.TransportError` while preparing, it prints `error: <message>` to stderr and returns 1.
  - `if __name__ == "__main__": raise SystemExit(main())`.

`prepare` does the following:
- Lists `/documents`. If any title is not a sample `.md` name, it raises `StackError` naming every foreign title: "the eval needs a stack holding only the samples in docs/samples/".
- Uploads each missing sample (`POST /documents`, multipart, `text/markdown`).
- Polls until every sample is `ready`. If a sample is `failed`, it raises `StackError("<title> failed: <error>; delete it and run again")`. Past `ready_timeout` it raises `StackError` naming the samples that are not ready.
- On a connect error it raises `StackError(f"cannot reach the API at {base_url}: {exc}")`.

`ask` posts `{"question": ...}` to `/ask` and reads the SSE stream with `httpx` `aiter_lines`:
- an `event:` line and a `data:` line make one event, and a blank line ends it;
- a `verdict` gives `answer = "\n\n".join(p["text"] for p in paragraphs)`, `label`, and `documents` (the cited `document_title`s in order, without repeats);
- an `error` event gives `Outcome(answer="", label=None, documents=(), error=detail, …)`;
- a stream that ends with neither gives the error "the stream ended without a verdict";
- a non-2xx response gives the error `HTTP <code>: <detail>`;
- `seconds` is the wall time of the call.
