# M5 — Ask Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user asks a question and gets an answer streamed over SSE, in which every paragraph is checked for valid `[n]` citations. The question is embedded, the closest chunks are retrieved, and Ollama writes the answer from them. If nothing relevant is found, no LLM is called. Every answer is stored in a browsable history, with citation snapshots that survive deleting the document.

**Architecture:**
- **Domain:** `fontes/domain/answers.py` holds `Paragraph`, `Citation`, `AnswerLabel` and `Answer`, the stored history record.
- **Application:**
  - a pure `verify()` for citation verification;
  - a pure `build_prompt()`;
  - an `AskService` that runs embed, search, the not-found shortcut, stream, verify and store, and yields `TokenEvent` and `VerdictEvent`;
  - new ports `LLMProvider` and `QuestionRepository`, plus `ChunkRepository.search`.
- **Adapters:**
  - `adapters/llm/ollama.py`: Ollama `/api/chat` streaming, via httpx;
  - `adapters/persistence/questions.py`: history in a `questions` table, with JSONB snapshots;
  - pgvector cosine search in `SqlChunkRepository`.
- **API:**
  - `POST /ask` is an SSE stream (`token`, `verdict`, `error`);
  - `GET /questions` and `GET /questions/{id}` serve the history.

**Tech Stack:** The M4 stack. There are no new runtime dependencies: SSE goes through Starlette's `StreamingResponse` with a small formatter of our own, and Ollama is called with httpx, without its SDK.

**Spec:** `docs/superpowers/specs/2026-11-03-fontes-design.md`. The relevant sections are "Ask flow", "Citation verification", "Citations", "History", "Anti-goals" and "Quality bar". Previous milestone: `docs/superpowers/plans/2026-11-07-m4-ingestion.md`.

## Global Constraints

- All M1–M4 Global Constraints still hold:
  - Python 3.12, `mypy --strict`, ruff, and the layering test;
  - integration tests are marked `integration`;
  - LF line endings;
  - commit and push per task;
  - **no co-author or AI attribution trailers**.
- The domain and application layers must not import httpx, sqlalchemy, fastapi, or any LLM SDK (already in `FORBIDDEN`).
- "Tests must not need Ollama or Claude. Use a fake `LLMProvider` and a fake `Embedder`."
- "If retrieval finds nothing relevant, the system says that it found nothing and does not call the LLM."
- "Support is checked **per paragraph** … A paragraph with no valid `[n]` marker is highlighted as unsupported. The answer as a whole is labelled `supported`, `partially_supported` or `unsupported`."
- "Split the answer into paragraphs on blank lines. A list item counts as its own paragraph." "A marker is valid only if `n` refers to a source that was actually provided to the model. Invalid markers are removed from the text."
- "Verification is a pure function in the application layer, with thorough unit tests."
- The SSE events are `token` (provisional text), `verdict` (the paragraphs with their flags, the label and the citations) and `error`.
- History stores "the question and the answer text; the paragraphs with their support flags; the overall label; the citations, as a snapshot of title, location, and excerpt, so history survives if the document is deleted; the provider and model used, and the timing."
- "History is stored for browsing, not fed back to the model." Every question stands alone.
- The integration tests must cover "the 'no relevant chunks means no LLM call' behaviour" and "discarding invalid citation markers".
- "For URLs, the citation also shows the link."
- `LLM_PROVIDER=ollama` is the default. The Claude provider is M7: this milestone defines the port so that M7 adds only an adapter and a config switch.

## Decisions for this milestone (designer's calls; the spec leaves them to the builder)

- **Chat model:** `qwen2.5:7b`, about 4.7 GB. It is a 7B instruct model that is good in both Russian and English and runs on CPU.
  - Settings:
    - `CHAT_MODEL` (`qwen2.5:7b`);
    - `LLM_TIMEOUT_SECONDS` (300.0, per read; a CPU model can take a minute before its first token);
    - `LLM_NUM_CTX` (8192);
    - `LLM_TEMPERATURE` (0.1).
  - **`num_ctx` is always sent.** Ollama's default context window is smaller than 6 sources of 1500 characters plus the instructions, and Ollama truncates the prompt silently, so the model would never see some sources.
  - The CI smoke job uses `CHAT_MODEL=qwen2.5:0.5b` (about 400 MB), so that pulling stays fast. It only checks that a verdict arrives, not how good the answer is.
- **Retrieval:**
  - Settings: `ASK_TOP_K` (6) and `ASK_MIN_SCORE` (0.45).
  - The score is cosine similarity, `1 - (embedding <=> q)`.
  - Only chunks of `ready` documents are searched.
  - A hit carries what a citation needs: the document id, title, url, the chunk, the document's total chunk count (for "part 3 of 12") and the score.
  - The total is computed only for the top-k rows: first select the top-k by distance, then count, so that the HNSW index serves the ordering.
  - Task 8 checks the threshold by hand against real `bge-m3` scores, and the README says that it is tunable.
- **The not-found answer:** the fixed text `I could not find anything about this in your documents.` is streamed as one `token`.
  - The verdict has the fourth label `not_found`, no paragraphs and no citations. A not-found answer makes no claim, so it is labelled `not_found`, not `unsupported`.
  - It is stored in history with `provider` and `model` null.
- **The prompt** (`build_prompt(question, hits) -> Prompt(system, user)`):
  - The system text pins these rules:
    - answer only from the numbered sources;
    - put at least one `[n]` marker in every paragraph and every list item;
    - if the sources do not answer the question, say so;
    - answer in the language of the question;
    - no headings.
  - The user text lists each source as `[n] {title} — {location}` (plus `({url})` for a URL document), then the chunk text, then the question.
  - Sources are numbered from 1, in score order.
- **Verification** (`verify(text, source_count) -> Verification(paragraphs, label)`):
  1. Normalize `\r\n` to `\n`.
  2. Split into blocks on blank lines (`\n[ \t]*\n`).
  3. Within a block, a line matching `^\s*(?:[-*+]|\d+[.)])\s+` starts a new list item. Any other line continues the current item, or the block's leading paragraph if no item has started yet.
  4. Strip each paragraph and drop the empty ones.
  5. A marker group matches `\[\s*\d+(?:\s*,\s*\d+)*\s*\]`. A number is valid if `1 <= n <= source_count`.
     - A group is rewritten as `[a][b]`, with its valid numbers deduplicated in order.
     - A group with no valid number is removed, together with the whitespace right before it.
  6. `Paragraph.citations` holds the paragraph's valid numbers, unique, in order of appearance. A paragraph is supported iff it has at least one.
  7. The label:
     - **no paragraphs at all is `unsupported`;**
     - all paragraphs supported is `supported`;
     - none supported is `unsupported`;
     - otherwise `partially_supported`.
  8. `Verification.text` is the cleaned paragraphs joined with `"\n\n"`. It is the answer text that gets stored.
- **Citations:**
  - The verdict lists one `Citation` per distinct cited number, sorted by `n`.
  - Each holds `n`, `document_id`, `document_title`, `location` (the `location_label`), `url` (null except for URL documents) and `excerpt` (the full chunk text, at most about 1500 characters).
  - Sources that were retrieved but never cited are not listed.
- **SSE (`POST /ask`, body `{"question": "..."}`):**
  - The question is stripped, and must be 1–2000 characters (`QUESTION_MAX_CHARS`); otherwise the request gets 422 before any stream starts.
  - The response is `text/event-stream`, with the headers `Cache-Control: no-cache` and `X-Accel-Buffering: no`.
  - Each event is `event: <name>\ndata: <one-line JSON>\n\n`. The events are:
    - `token`: `{"text": str}`;
    - `verdict`: `{"question_id", "label", "paragraphs": [{"text", "supported", "citations": [n]}], "citations": [{"n", "document_id", "document_title", "location", "url", "excerpt"}]}`;
    - `error`: `{"detail": str}`.
  - Everything after validation happens inside the stream. Any exception (Ollama down, model missing, database down) ends the stream with one `error` event carrying `str(exc)`, and **nothing is stored**.
  - If the client disconnects, the generator is cancelled and nothing is stored.
- **History:**
  - Migration `0003_questions` creates the table `questions`. Columns:
    - `id uuid pk`;
    - `question text not null`;
    - `answer text not null`;
    - `label text not null`;
    - `paragraphs jsonb not null`;
    - `citations jsonb not null`;
    - `provider text null`;
    - `model text null`;
    - `duration_ms int not null`;
    - `created_at timestamptz not null`.

    It has an index `ix_questions_created_at`. There is no foreign key to `documents`: the citations are snapshots.
  - `GET /questions` returns the newest 50 as `[{"id", "question", "label", "created_at"}]`.
  - `GET /questions/{id}` returns the full record, and 404 for an unknown id.
  - `duration_ms` is wall-clock time from the start of `ask()` to the verdict.
- **Ollama chat adapter:**
  - It sends `POST /api/chat` with this body:
    ```json
    {"model": "...", "stream": true,
     "messages": [{"role": "system", ...}, {"role": "user", ...}],
     "options": {"num_ctx": ..., "temperature": ...}}
    ```
  - It reads NDJSON lines and yields each `message.content` that is not empty, until `done`.
  - Errors are mapped as in `OllamaEmbedder`:
    - a timeout is `TimeoutError("Ollama at {url} did not answer in time …")`;
    - a transport error is `ConnectionError("Cannot reach Ollama at {url}: …")`;
    - a 404 with "not found" is `RuntimeError` with ``run `ollama pull {model}` ``;
    - an `{"error": ...}` line in the middle of the stream is `RuntimeError("Ollama: {error}")`.
- **Compose:**
  - `ollama-pull` runs `sh -c "ollama pull bge-m3 && ollama pull $${CHAT_MODEL}"`, with `CHAT_MODEL: ${CHAT_MODEL:-qwen2.5:7b}`.
  - `api` gets `OLLAMA_URL` and `CHAT_MODEL`, and depends on `ollama` being healthy, not on the pull. Uploads work while the models download, and `/ask` before then fails with the "ollama pull" error event.
- **Folded-in deferred minors:**
  - *[M5] tiny chunks:* sentence and space cuts also need to be past half the window (this changes M4 rule 3: paragraph, then sentence, then space, each only past half; otherwise a hard cut).
  - *[M5] `list_for_document` loads embeddings:* defer the column.
  - *[any] `ChunkRow` lacks `ix_chunks_embedding`:* declare it, because search now depends on it. A test compares the models with the migrations.

## Review Focus

- **The model writes markers for sources it was not given** (`[7]` with 3 sources, `[0]`, `[1, 7]`, `[ 2 ]`). Valid numbers must survive, invalid ones must vanish from the text without leaving a stray space before punctuation, and a paragraph left with no valid marker becomes unsupported. Pinned in Task 2 (`test_out_of_range_markers_removed`, `test_group_keeps_only_valid_numbers`) and Task 7 (the integration test `test_invalid_markers_are_discarded_end_to_end`).
- **An empty or whitespace-only model answer.** Taking `all()` over zero paragraphs would label it `supported`. It must be `unsupported`. Pinned in Task 2 (`test_empty_answer_is_unsupported`).
- **The prompt is longer than Ollama's default context.** The model would silently not see some sources and then cite numbers whose text it never read. `num_ctx` must always be sent. Pinned in Task 6 (`test_request_sends_num_ctx_and_temperature`).
- **Ollama is down, or the chat model is not pulled yet, when someone asks.** The stream must end with one `error` event naming Ollama or saying `ollama pull`, and history must stay empty. Pinned in Task 5 (`test_llm_failure_stores_nothing`), Task 6 (`test_model_missing_raises_clear_error`) and Task 7 (`test_error_event_when_llm_fails`).
- **The cited document is deleted after the answer.** The history record must still show its title, location and excerpt. Pinned in Task 4 (`test_history_survives_document_delete`).
